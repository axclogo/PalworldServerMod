# 游戏内验收

验收环境为 Linux 宿主通过 Wine 运行 Windows 专服，远程玩家使用 Windows Steam。两端各装 UE4SS、PalSchema 和本整合包。首次测试采用两份包的默认设置。单人存档副本可以先查石像、信赖、商店和本地读档；专服扣款、远程鱼获和停服重启后的结果要在专服副本上确认。

## 当前已知问题

**竞技场。** 上一包的实机表现是技能果实之后有 14 个灰格，全部显示 9999999。该数字正是原版商店价格控件的默认文字。Steam 当前 Windows 专服的商品结构写作 `StaticItemID`，客户端 1.0.5 反射表写作 `StaticItemId`。按 PalSchema 逐字段、区分大小写的写法重放专服原表，旧包能匹配 0 个新增物品编号，本包匹配 14 个。每件商品只追加一次。还需一次联机确认实际显示、扣券和到账。[PalSchema 字段写入](https://github.com/Okaetsu/PalSchema/blob/302b4ffe958d219762058cade48685ef010723d8/src/SDK/Helper/PropertyHelper.cpp#L352-L374) · [客户端反射数据](https://github.com/PalworldModding/UsefulFiles/commit/acdf1a6a6076f84fae3275e7c1cdd08188994da8)

**滑翔伞。** 原版专属伞自己也接收展开事件，天擒鸟和鲁米儿的伞面默认冻结骨架。修订后的玩家包处理这个事件，在显示搭档时启用兼容的飞行动画，收伞时还原更新开关。已核对原版搭档表的七个物种与变种、35 个实际装备类。外观、动作和队友视角待实机确认。

**去雾与卡顿。** 游戏用窗口的区域列表管理主地图和世界树地图。玩家包在地图初始化、应用遮罩和切区时处理探索雾，已移除地图定时检查。已展开的普通伞重复收到同样的外观刷新时，也省去一轮恢复和替换模型。游玩帧率和服务端响应尚未实测。

## 人物已经能动后，游玩仍卡

**当前实机反馈仍然卡，此项待定位。** 读档耗时和离线脚本调用次数都无法回答游玩中的卡顿来自哪一端。复用同一次游玩，在出现卡顿的位置看一次读数即可。

按 Esc 打开「服务器信息」（Server Info，在玩家列表旁），查看 Server FPS、RTT（往返延迟）、Jitter（延迟波动）和 PacketLoss（丢包）。本机帧率可在 Steam 的「设置 → 游戏中 → 性能监视器」显示，最低帧率有助于看到平均值掩盖的顿帧。和同一次游玩较流畅时相比，Server FPS 明显下降时优先查服务器模拟；服务器帧率稳定而延迟、波动或丢包同时升高时优先查连接；前面几项稳定而本机帧率下跌时优先查玩家端。多项同时异常时分别保留，各项读数用于定位方向，不能直接归因到某个 Mod。[游戏内服务器信息实图](https://help.dathost.net/article/152-palworld-performance-and-lag-issues) · [Steam 性能监视器](https://help.steampowered.com/en/faqs/view/3462-CD4C-36BD-5767)

## 一次联机验收

1. **服主先备好副本和材料。** 正常停服，备份完整的 `Pal/Saved/`，另开独立实例。保留与备份配套的两端旧包和前置。双方一次装好本目录的对应 ZIP。测试角色需有 **2,600 张战斗券**才能买齐 14 件。14 种植入物各手术一次，任选一种再给第二只帕鲁使用一次，共需 **750 万金币**，其中一部分留在可分开取出的储备里。四项从 20 升到 80 共需 **5,040 个究极帕鲁之魂**；已有接近测试档位的帕鲁可直接用。另备有未探索区域的角色、已解锁的滑翔搭档和普通伞，以及鱼竿和饵。[服主安装说明](服主安装.txt)
2. **先测已报告的四个现象。** 服主和玩家分别记下同一存档、同一环境从启动到可加入、从加入到可操作的耗时。有旧包基线时才比较。打开竞技场逐项查看商品名、芯片图标、票价，再购买。打开大地图查看已知未探索区域，关掉再打开。轮流使用天擒鸟和另一种搭档滑翔，自己和队友都观察一次，再移走搭档检查普通伞。
3. **同一次联机测其余功能。** 按下表做手术、升魂、信赖、基地合并和两人钓鱼，记录操作前后的金币、材料、属性与鱼获。已有低余额角色先做 499999 金币的不足额手术。高信赖和升魂上限使用预先准备的样本，缺少样本的项目保留为待验。
4. **一起保存和重启一次。** 两人退出，正常停服并重启副本，再以原角色加入，核对购买记录、植入物、帕鲁词条、魂等级、信赖属性和鱼获。离线已通过、实机已通过、缺样本未测的项目分别记录。正式世界继续保留原备份。

## 加载和已有存档

先在副本中核对原有基地、帕鲁和物品，再执行购买或升级。PalSchema 读档时会把无法识别的物品清空。若日志出现本包植入物 ID 后接 `is invalid. Deleting.`，保留启动前的备份，确认物品定义能加载后再从备份副本开始。[加载器的读档处理](https://github.com/Okaetsu/PalSchema/blob/302b4ffe958d219762058cade48685ef010723d8/src/Loader/PalItemModLoader.cpp#L554-L574)

升魂由游戏直接读取 PAK。双端均应装有 `Pal/Content/Paks/~mods/PalSoulCap80_P.pak`。石像的第一处关键检查是单项 20→21，界面应显示 10 个究极帕鲁之魂；成功后再核对实际扣料及重连结果。信赖仍通过 PalSchema 新增 89 行，可在本次 UE4SS 日志核对信赖表及植入物登记。

## 成长、商店与手术台

| 操作 | 验收条件 |
| --- | --- |
| 四项属性分别做 20→21、25→26、79→80。取一次只差一个材料的情况，再补足材料 | 每项分别扣 10、12、32 个究极魂，材料不足时等级与余额保持。80 时升下一档不可用。核对同一只帕鲁升级前后的实际属性、其余三项等级与重启结果 |
| 在副本中重置已超 20 级的帕鲁 | 记录可见报价与实际扣款，对照原版同一操作的退款规则，逐种核对返魂与最终等级。数据行中的 30000 只代表该行重置参数 |
| 两个原生信赖系数不同的物种，分别跨过 10→11、98→99，在 11、26、99 级保存重启；99 后再获得经验 | 11 级达到 250000 点，99 级达到 4650000 点，等级封顶 99。固定等级、词条和升魂，观察各物种有非零系数的属性确实继续增长。重连后核对实际生命、攻击、防御及面板 |
| 比较启用前后竞技场库存，用测试角色购买全部 14 项，重访并重启 | 保留当前构建原有商品，每个新增项只出现一次；传说与四个自定义项各扣 250 竞技场币，九个帝王项各扣 150。该角色再次访问不能重复购买 |
| 先持有 499999 金币尝试手术，再补足 500000，更换目标帕鲁再次使用同一种植入物 | 余额不足时保留金币和原词条。成功时每次实扣 500000 金币，原生永久植入物继续可用。重启后两只帕鲁的词条、玩家植入物与限购状态均保留 |

四个虹色词条用同一只帕鲁、同等级、无其它影响该指标的词条对照。**白猪战车**核对最大生命与防御，另检查受伤状态下收回、放出是否异常回血。**宅断腿**以相同食物、工作和时间比较基地内 SAN、饱食、移动和工作完成时间，再调离基地检查四项效果是否解除。**凯旋山野**分别比较草系与非草系技能对同一目标的伤害。另选一只会草技能的非草系帕鲁做同样对照，确认草伤加成由技能属性决定。**纸老虎**比较攻防变化与原版鬼神、双刃圣剑在同条件下的相对收益。最后用同一只帕鲁组合高信赖、升魂 80 和白猪战车，核对受击、治疗、重连和重启后生命上限，固定其他变量后判断是否截断。

## 基地、钓鱼与客户端显示

| 场景 | 验收条件 |
| --- | --- |
| 基地内放两组已知数量的同类物品，分别明显小于、明显大于 5 米，再混入另一种物品。刚载入或新建的基地先留出一次 15 秒检查周期。检查地上、仓库和背包 | 近距离可合并，异类分开。人工拾取与帕鲁搬运前后总数相同，满堆附近也不会丢失或复制。5 米指物品间合并距离 |
| 已有基地重启后观察牧场的首批自然掉落，并在玩家离开、返回后检查发电与搬运 | 游戏为各基地共用这组距离档位。换到第二个已有基地也应能合并，基地外的掉落保持原生行为。性能结论需要相同产量下的服务端实测 |
| 两个独立客户端同场钓普通与稀有鱼，分别取消、连续重抛、骑乘、断线 | 正常咬钩后每轮每人只获得对应的一份奖励。取消的旧轮次不能替新轮次结算。以服务端确认的背包、鱼饵变化和重连后持有量为准 |
| 用有未探索区域的角色打开大地图，关闭重开、切换区域后再开；移走地图组件并重启 | 每次打开可见未探索地形，未解锁传送点仍需解锁。停用重启后未探索区域恢复原版迷雾 |
| 带已解锁的滑翔搭档及原版滑翔伞起跳，换另一物种再试，两人交替观察。移走搭档，再试普通伞和喷气背包 | 搭档滑翔时显示对应物种，留意姿势、握点以及两人所见。普通伞与喷气背包显示原装备，原版速度、收伞与着陆正常 |
