# 据点工作帕鲁扩容 60

把每个据点的工作帕鲁上限从原版（等级表 1→30，且被世界设置压到 15）提高到 **60**，并让它在据点等级 30 时达到上限，31 级以后维持 60。

## 机制

实际生效数量是两者取小：

```
每据点工作帕鲁 = min(据点等级给的 WorkerMaxNum, 世界设置 BaseCampWorkerMaxNum)
```

- **等级表**：`DT_BaseCampLevelData`（35 行，字段 `Level` / `WorkerMaxNum` / `BaseCampMaxNumInGuild`）。原版 1 级 1 只，逐级 +1，30 级到 30 之后不再涨。本包改成每级 +2、30 级 60、31–35 级保持 60。
- **世界设置**：`BaseCampWorkerMaxNum` 原版 15、**官方上限 50**。必须同步改成 60，否则会被压回去，见下方「服主要改的」。

## 服主要改的（不随包）

`PalWorldSettings.ini` 的 `OptionSettings` 里加/改：

```ini
BaseCampWorkerMaxNum=60
```

如果改完进游戏还是 15 或 50，说明这个值以 `WorldOption.sav` 为准，需要在服务端面板里改，或者用官方参数页对照；详情见[排查与踩坑记录](../../../docs/TROUBLESHOOTING.md)。

## 风险与边界

- **官方上限是 50**：官方参数表把 `BaseCampWorkerMaxNum` 写作 max 50。60 属于越界值，可能被程序夹回 50；实机不生效就需要客户端 pak 解锁滑块（社区 100/150/200 版本就是这么做的）。
- 60 只帕鲁同据点，寻路与工作调度开销明显，Server FPS 会掉；社区同类模组都标注"提高处理负载"。
- 超出原版设计后可能出现帕鲁挤在同一工作点、寻路卡顿。
- 只改工作帕鲁数量，不动公会据点数（原版 1→4，官方设置上限 10）。
- 双端都要有这份数据，客户端才显示对应工作槽位。
- 未核对：实际槽位数量、60 只同时工作、重启与重连后的保留。
